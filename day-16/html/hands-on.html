Day 16: Prototypes and the Prototype Chain

Hands-on: Guided Practice

Hands-on Exercises

Task 1: Inspect a Prototype

What to do: Create const arr = [1, 2, 3];. Use Object.getPrototypeOf(arr) and log it. What is it? Now log Object.getPrototypeOf(Object.getPrototypeOf(arr)). What is it? And once more — log the next step. What value ends the chain? In a comment, draw the chain.

const arr = [1, 2, 3];
console.log(Object.getPrototypeOf(arr)) // Array.prototype
console.log(Object.getPrototypeOf(Object.getPrototypeOf(arr))) // Object.prototype
console.log(Object.getPrototypeOf(Object.getPrototypeOf(Object.getPrototypeOf(arr)))) // null

// Prototype Chain:
//
// arr
//  ↓
// Array.prototype
//  ↓
// Object.prototype
//  ↓
// null

/*
Explanation:
1. arr is an array instance created with [] syntax
2. Its prototype is Array.prototype (has methods like push, pop, forEach)
3. Array.prototype's prototype is Object.prototype (has toString, hasOwnProperty)
4. Object.prototype's prototype is null (end of the chain)

This is why arrays can use both array methods (from Array.prototype)
and object methods (from Object.prototype)
*/

Task 2: Build with Object.create

What to do: Create an object vehicle with method start() { console.log(`${this.name} starting`); }. Use Object.create(vehicle) to make car and set car.name = "Tata Nexon". Make bike the same way with name = "Royal Enfield". Call start() on both. Use hasOwnProperty and in to confirm name is own and start is inherited.

const vehicle = {
    start(){
        console.log(`${this.name} starting`);
    }
}

const car = Object.create(vehicle)
car.name = "Tata Nexon"

const bike = Object.create(vehicle)
bike.name = "Royal Enfield"

car.start()  // "Tata Nexon starting"
bike.start() // "Royal Enfield starting"

// Check ownership vs inheritance
console.log(car.hasOwnProperty("start"))  // false - start is inherited
console.log("start" in car)               // true - start is accessible via prototype

console.log(car.hasOwnProperty("name"))   // true - name is own property
console.log("name" in car)                // true - name is own property

/*
Key insight:
- hasOwnProperty() checks ONLY the object's direct properties
- in operator checks both own properties AND inherited properties
- car and bike share the same start method (memory efficient)
- Each has its own name property (instance-specific data)
*/

Task 3: Constructor Function Inheritance

What to do: Build a Person(name) constructor that sets this.name = name. Add Person.prototype.greet = function () { console.log("Hi, I'm " + this.name); }. Build a Student(name, school) constructor that calls Person.call(this, name) and sets this.school = school. Link Student.prototype to inherit from Person.prototype using Object.create. Add Student.prototype.study = function () { console.log(this.name + " studies at " + this.school); }. Create a new Student("Riya", "IIT Delhi") and call both greet and study.

function Person(name){
    this.name = name
}

Person.prototype.greet = function(){
    console.log("Hi, I'm " + this.name)
}

function Student(name, school){
    Person.call(this, name)  // Inherit Person's constructor behavior
    this.school = school;
}

// Set up prototype inheritance
Student.prototype = Object.create(Person.prototype);
Student.prototype.constructor = Student; // Restore constructor reference

Student.prototype.study = function(){
    console.log(this.name + " studies at " + this.school)
}

const student = new Student("Riya", "IIT Delhi")
student.greet();  // "Hi, I'm Riya" - inherited from Person
student.study();  // "Riya studies at IIT Delhi" - own to Student

/*
Inheritance chain:
student → Student.prototype → Person.prototype → Object.prototype → null

Key steps:
1. Person.call(this, name) - borrows Person's constructor
2. Object.create(Person.prototype) - links Student to Person prototype chain
3. Student.prototype.constructor = Student - maintains proper constructor reference
4. Now Student instances can access both Person and Student methods
*/

Bonus: hasOwnProperty vs in

What to do: Create const dog = Object.create({ species: "Canis" }); dog.name = "Bruno";. Predict the result of: dog.hasOwnProperty("name"), dog.hasOwnProperty("species"), "name" in dog, "species" in dog, "toString" in dog. Run all five. Match against your prediction. In a comment, write the one-line rule for when to use which.

const dog = Object.create({species: "Canis"});
dog.name = "Bruno";

// Test and predict each one:
console.log(dog.hasOwnProperty("name"))     // true - name is directly on dog
console.log(dog.hasOwnProperty("species"))  // false - species is on prototype
console.log("name" in dog)                  // true - name exists (own property)
console.log("species" in dog)               // true - species exists (via prototype)
console.log("toString" in dog)              // true - toString exists (via Object.prototype)

/*
One-line rules:

hasOwnProperty() → "Is this property directly on THIS object?"
in operator      → "Can I access this property from this object?"

Use hasOwnProperty() when you want to check only direct/own properties
Use in operator when you want to check if property is accessible (own OR inherited)

Real-world example:
for (let key in dog) {
  if (dog.hasOwnProperty(key)) {
    console.log(key + " is dog's own property");
  }
}
// This pattern prevents iterating over inherited properties
*/
