Hands-on Exercises

Task 1: Sync vs Async Output

What to do: Type: console.log("A"); setTimeout(() => console.log("B"), 0); console.log("C"); Promise.resolve().then(() => console.log("D"));. Predict the output order BEFORE running. Run. Note the actual order. In a comment, explain why D comes before B even though both are "async with delay 0".

console.log("A");
setTimeout(() => console.log("B"), 0);
console.log("C");
Promise.resolve().then(() => console.log("D"));

// Predicted output: A, C, D, B
// Actual output: A, C, D, B

/*
Why D comes before B:

1. A and C are synchronous → execute immediately first
2. setTimeout callbacks go to the MACROTASK queue
3. Promise.then callbacks go to the MICROTASK queue  
4. After sync code finishes, JavaScript event loop processes:
   - ALL microtasks first (D runs)
   - Then macrotasks (B runs)
5. → D (microtask) always runs before B (macrotask)

This is fundamental to JavaScript's event loop:
Microtasks have higher priority than macrotasks!
*/

Task 2: Promisify a Callback API

What to do: Take this callback-style function: function delayLog(msg, ms, cb) { setTimeout(() => { console.log(msg); cb(null); }, ms); }. Wrap it in a Promise-returning version delayLogPromise(msg, ms). Use it to chain three logs: "1" after 300ms, then "2" after 200ms, then "3" after 100ms.

function delayLog(msg, ms, cb){
    setTimeout(() =>{
        console.log(msg);
        cb(null);
    }, ms)
}

function delayLogPromise(msg, ms){
    return new Promise((resolve, reject)=>{
        delayLog(msg, ms, (error) =>{
            if(error) reject(error);
            else resolve();
        })
    })
}

delayLogPromise("1", 300)
.then(()=> delayLogPromise("2", 200))
.then(()=> delayLogPromise("3", 100));

/*
Output (sequential timing):
"1" (after 300ms)
"2" (after 500ms total - 300+200)
"3" (after 600ms total - 300+200+100)

Key concepts:
1. Promisification wraps callback APIs in Promise interface
2. Promise chain ensures sequential execution
3. Each .then waits for previous promise to resolve
4. Total time is sum of all delays (sequential, not parallel)
*/

Task 3: Promise.all in Action

What to do: Write a function fetchPrice(item, ms) that returns a Promise resolving to a price object after ms milliseconds. Use this data: pen → 50, book → 200, bag → 800. Use Promise.all to fetch all three in parallel. Sum the prices and log the total. Time the whole thing with Date.now() — confirm it's near the SLOWEST item, not the sum.

const prices = {
    pen: 50,
    book: 200,
    bag: 800
};

function fetchPrice(item, ms){
    return new Promise((resolve, reject) =>{
        setTimeout(() =>{
            resolve({
                item: item,
                price: prices[item]
            });
        }, ms)
    });
}

const start = Date.now();

Promise.all([
    fetchPrice("pen", 1000), 
    fetchPrice("book", 2000), 
    fetchPrice("bag", 3000)
])
.then((results) =>{
    console.log(results);
    const total = results.reduce((acc, curr) => {
        return acc + curr.price;
    }, 0);
    
    const elapsed = Date.now() - start;
    console.log(`Total price: ${total}`);
    console.log(`Time taken: ${elapsed}ms`);
})

/*
Expected output:
[
  { item: "pen", price: 50 },
  { item: "book", price: 200 },
  { item: "bag", price: 800 }
]
Total price: 1050
Time taken: ~3000ms (near the slowest item)

Key insights:
1. Promise.all runs operations in PARALLEL
2. Total time ≈ slowest operation (3000ms), NOT sum (6000ms)
3. All promises start immediately, resolve at their own pace
4. Promise.all waits for ALL to complete before resolving
*/

Bonus: Promise.allSettled vs Promise.all

What to do: Take three promises: Promise.resolve("ok1"), Promise.reject(new Error("fail")), Promise.resolve("ok2"). First wrap them in Promise.all — what happens? Now wrap them in Promise.allSettled — what happens? In a comment, explain when you'd reach for each.

const p1 = Promise.resolve("ok1");
const p2 = Promise.reject(new Error("fail"));
const p3 = Promise.resolve("ok2");

// Test Promise.all
Promise.all([p1, p2, p3])
.then((results) => {
    console.log("Promise.all success:", results);
})
.catch((error) => {
    console.log("Promise.all failed:", error.message);
});

// Test Promise.allSettled
Promise.allSettled([p1, p2, p3])
.then((results) => {
    console.log("Promise.allSettled results:");
    results.forEach((result, index) => {
        if (result.status === "fulfilled") {
            console.log(`  ${index}: SUCCESS -`, result.value);
        } else {
            console.log(`  ${index}: FAILED -`, result.reason.message);
        }
    });
})
.catch((error) => {
    console.log("Promise.allSettled failed:", error); // This won't run
});

/*
Output:
Promise.all failed: fail
Promise.allSettled results:
  0: SUCCESS - ok1
  1: FAILED - fail
  2: SUCCESS - ok2

When to use Promise.all():
- Use when ALL operations must succeed
- If ANY operation fails, the whole batch should fail
- Example: Must have user data, settings, and permissions to proceed

When to use Promise.allSettled():
- Use when you want results from ALL operations even if some fail
- Partial success is acceptable
- Example: Loading multiple widgets - show the ones that work
*/
