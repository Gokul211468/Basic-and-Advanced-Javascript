Event Loop Exercises

Task 1: Predict the Output

What to do: Type this exactly, predict the output BEFORE running, then run and match against your prediction. In a comment, list which lines were sync, which microtask, which macrotask.

console.log("1");
setTimeout(() => console.log("2"), 0);
Promise.resolve().then(() => console.log("3"));
console.log("4");

// PREDICTION: 1, 4, 3, 2
// ACTUAL OUTPUT: 1, 4, 3, 2 ✅

// Execution analysis:
// Line 1: console.log("1") - SYNCHRONOUS - executes immediately
// Line 2: setTimeout(..., 0) - MACROTASK - queued for later
// Line 3: Promise.resolve().then(...) - MICROTASK - queued with high priority  
// Line 4: console.log("4") - SYNCHRONOUS - executes immediately

// Execution order:
// 1. Run all synchronous code first → Output: "1", "4"
// 2. Drain microtask queue completely → Output: "3"  
// 3. Execute one macrotask → Output: "2"

/*
Key insight: Even setTimeout(0) doesn't mean "now" - it means 
"queue this for execution after all sync code and microtasks complete"
*/

Task 3: Block the Loop

What to do: Write a blockFor(ms) that busy-waits for ms milliseconds (use a while with Date.now()). Schedule a setTimeout(() => console.log("timer"), 100). Immediately call blockFor(2000) then console.log("after block"). Note the timer doesn't fire until well after 100ms.

function blockFor(ms) {
    const start = Date.now();
    // WARNING: This is a BLOCKING operation - don't do this in real apps!
    while (Date.now() - start < ms) {
        // Busy-wait loop - burns CPU and blocks everything
    }
    console.log(`Done blocking for ${ms}ms`);
}

// Schedule a timer for 100ms
setTimeout(() => {
    const elapsed = Date.now() - startTime;
    console.log(`Timer fired after ${elapsed}ms (expected ~100ms)`);
}, 100);

const startTime = Date.now();

// Block the main thread for 2 seconds
blockFor(2000);

console.log("After blocking");

/*
Expected Output:
(2+ second pause while blocking)
Done blocking for 2000ms
After blocking  
Timer fired after ~2000ms (expected ~100ms)

Key insights:
1. The setTimeout callback can't execute until the call stack is clear
2. blockFor(2000) holds the call stack hostage for 2 full seconds  
3. Even though we set a 100ms timer, it fires after 2000ms
4. This demonstrates why JavaScript is "single-threaded" - 
   one blocking operation freezes everything
5. In a real browser, the entire tab would be frozen during blocking
   - No scrolling, clicking, or other interactions possible
   - This is why we break up heavy work with setTimeout/web workers

Performance lesson: NEVER write blocking code like this in production!
*/

Bonus: Microtask Storm

What to do: Write a function that schedules 5 setTimeout(fn, 0) calls. Inside ONE of the timers, schedule 3 Promise.resolve().then(...). Predict the output. Run. Verify. In a comment, explain how microtasks "starve" macrotasks if abused.

// Schedule 5 timers
for (let i = 1; i <= 5; i++) {
    setTimeout(() => {
        console.log(`Timer ${i}`);
        
        // In the 3rd timer, create a "microtask storm"
        if (i === 3) {
            console.log("  Creating microtasks...");
            Promise.resolve().then(() => console.log("  → Promise 1"));
            Promise.resolve().then(() => console.log("  → Promise 2"));  
            Promise.resolve().then(() => console.log("  → Promise 3"));
        }
    }, 0);
}

/*
Expected Output:
Timer 1
Timer 2  
Timer 3
  Creating microtasks...
  → Promise 1
  → Promise 2
  → Promise 3
Timer 4
Timer 5

Execution Flow:
1. All 5 timers get queued as macrotasks
2. Event loop picks Timer 1 → executes → checks microtasks (none)
3. Event loop picks Timer 2 → executes → checks microtasks (none)  
4. Event loop picks Timer 3 → executes → creates 3 microtasks
5. Before moving to Timer 4, event loop MUST drain ALL microtasks
   → Promise 1, Promise 2, Promise 3 all execute
6. Only then can Timer 4 and Timer 5 execute

MICROTASK STARVATION WARNING:
If microtasks keep creating more microtasks indefinitely:

Promise.resolve().then(function createMore() {
    console.log("Microtask running...");
    Promise.resolve().then(createMore);  // Creates another microtask!
});

setTimeout(() => console.log("This will NEVER run!"), 0);

This would create an infinite loop of microtasks, preventing ANY macrotasks 
from ever executing. The setTimeout would be starved forever.

Real-world implications:
- User interactions (clicks, scrolls) are macrotasks
- If you create too many microtasks, the UI becomes unresponsive  
- Always be careful with recursive Promise chains
- Break up heavy Promise work with occasional setTimeout(0) to yield
*/
