Homework Exercises

Exercise 1: `this` Context Exploration

What to do: Build an object user = { name, greet } where greet logs this.name. Now call user.greet(), const fn = user.greet; fn(), and user.greet.call({ name: "X" }). Predict each first, then run.

const user = {
    name: "Priya",
  
    greet() {
      console.log(this.name);
    }
  };
  
  /*
  Predictions:
  
  user.greet()                  -> "Priya"
  fn()                          -> undefined
  user.greet.call({name:"X"})   -> "X"
  */
  
  // Method call
  user.greet();
  
  // Store function separately
  const fn = user.greet;
  
  // Plain function call
  fn();
  
  // call() sets this manually
  user.greet.call({ name: "X" });
  
  /*
  Actual Output:
  Priya
  undefined
  X
  
  Why?
  
  user.greet()
  -> this = user (implicit binding)
  
  fn()
  -> plain function call
  -> this = undefined (strict mode)
  
  call({name:"X"})
  -> this is manually set to {name:"X"} (explicit binding)
  */

Exercise 2: Using apply with Arrays

What to do: Write function sum(...nums) { return nums.reduce((a, b) => a + b, 0); }. Use .apply to call it with an array [1, 2, 3, 4, 5]. Why does .apply shine here?

function sum(...nums) {
    return nums.reduce((a, b) => a + b, 0);
  }
  
  const arr = [1, 2, 3, 4, 5];
  
  // Using apply
  const result = sum.apply(null, arr);
  
  console.log(result); // 15
  
  /*
  Why apply shines here:
  
  apply lets us pass an array as function arguments.
  
  Without apply:
  sum(1, 2, 3, 4, 5)  // have to list each number
  
  With apply:
  sum.apply(null, [1, 2, 3, 4, 5])  // can use existing array
  
  So apply is useful when:
  1. Arguments already exist in an array
  2. You want to "spread" array elements as separate parameters
  3. You need to call a function that expects separate args but you have an array
  
  Note: In modern JS, you can also use the spread operator:
  sum(...arr)  // equivalent to sum.apply(null, arr)
  */

Exercise 3: Arrow Functions and Binding

What to do: Take an arrow function const f = () => console.log(this) written at top-level of a module. Try to .bind({ x: 1 }) it and call. What does it log? Why?

// Top-level arrow function
const f = () => console.log(this);

// Try to bind a new this
const boundF = f.bind({ x: 1 });

// Call it
boundF();

/*
Output in ES modules:
undefined

(inside browsers without modules it may log window)

Why?

1. Arrow functions inherit this lexically from where they're defined
2. At the top level of an ES module, this is undefined
3. Arrow functions CANNOT be rebound - bind() has no effect
4. The arrow function will always use the this from its creation context
5. Even explicit binding attempts (call, apply, bind) are ignored

This demonstrates that arrow functions:
- Don't have their own this
- Cannot be rebound
- Always use lexical this from definition site
- Are NOT suitable when you need dynamic this binding

Key takeaway: Use regular functions when you need bindable/rebindable this
Use arrow functions when you want to preserve lexical this context
*/
